# Порівняння способів зв'язку

Застосунок надсилає зміну статусу події через ASP.NET Core SignalR. Сторінка `/Live` одразу змінює позначку статусу в іншій вкладці. Для порівняння на цій самій сторінці можна примусово вибрати три транспорти SignalR: WebSockets, Server Sent Events і Long Polling. У всіх трьох випадках виконується той самий хабовий виклик `Echo` 20 разів поспіль.

## Методика

Дата заміру: 24 вересня 2026 року, 12:19 UTC. Windows 10, Chrome 153, клієнт і сервер на `127.0.0.1`. Кожен виклик має рядок `event-benchmark-NN-` і 64 символи `x`. Браузер вимірює час підключення й round-trip time через `performance.now()`. Кількість HTTP-запитів і переданих HTTP-байтів береться з браузерного Resource Timing для `/hubs/events` від початку підключення до завершення. [Сирі значення](../evidence/transport-benchmark-2026-09-24.json) збережені окремо.

| Транспорт | Підключення | Медіана RTT | HTTP-запитів | HTTP-байтів |
| --- | ---: | ---: | ---: | ---: |
| WebSockets | 15.1 мс | 0.35 мс | 1 | 616 |
| Server Sent Events | 24.9 мс | 3.85 мс | 22 | 6 916 |
| Long Polling | 22.8 мс | 4.50 мс | 47 | 16 629 |

На цьому локальному сценарії WebSockets мав найменшу медіану RTT і найменше число окремих HTTP-запитів. Long Polling створив найбільше HTTP-запитів та HTTP-байтів. Це один короткий замір, а не узагальнення для мобільної мережі чи багатьох одночасних користувачів. Resource Timing не враховує кадри WebSocket у колонці HTTP-байтів, тому 616 байтів не є повним трафіком WebSockets. Пам'ять і CPU процесу окремо не вимірювалися; висновків щодо них немає.

Повторення: запустити застосунок, відкрити `/Live`, натиснути «Запустити замір», переглянути таблицю й завантажити JSON. Для перевірки доставки відкрити `/Live` у першій вкладці, змінити статус події через `/Events/Edit/{id}` у другій і пересвідчитися, що перша вкладка показала новий статус без перезавантаження.

Використані API: [документація SignalR JavaScript client](https://learn.microsoft.com/en-us/aspnet/core/signalr/javascript-client?view=aspnetcore-8.0), [підтримувані транспорти SignalR](https://learn.microsoft.com/en-us/aspnet/core/signalr/configuration?view=aspnetcore-8.0#configure-allowed-transports-1).
