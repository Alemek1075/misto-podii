# Місто подій: специфікація

## Мета

Вебзастосунок для пошуку локальних подій. Відвідувач знаходить подію за датою, темою та місцем, відкриває її окрему сторінку й бачить спосіб зв'язку з організатором. Редактор створює та змінює організаторів, місця й події. Демонстраційні дані не містять справжніх контактів приватних осіб.

## Предметна модель

- **Організатор**: назва, опис, публічний контакт, вебсайт.
- **Місце**: назва, адреса, широта, довгота, місткість.
- **Подія**: назва, опис, дата й час у UTC, категорія, URL зображення, організатор і місце.
- Один організатор і одне місце можуть мати багато подій. Видалення сутності, яку використовують події, заборонене з поясненням користувачеві.

URL зображення є файловим посиланням у межах вимоги C1. Завантаження файлів і зовнішнє сховище належать до окремої вимоги C19.

## Технології та межі

ASP.NET Core MVC на .NET 8, Entity Framework Core та SQLite. Сторінки рендеряться сервером через Razor. Bootstrap уже входить у шаблон MVC. Публічний JSON API користується тією самою моделлю та базою. Схема зберігається через EF Core migrations. Проєкт має запускатися локально без платних сервісів і ключів.

Робочий інтерфейс українською. Дані зберігаються у SQLite. Час події вводиться у місцевому часовому поясі інтерфейсу, а в базі зберігається UTC; до реалізації цього перетворення інтерфейс повинен чітко позначати UTC.

## Плановані вимоги курсу

| Код | Результат, який можна продемонструвати |
| --- | --- |
| C1 | Три пов'язані сутності, MVC CRUD, посилання на зображення |
| C5, B1, QA1 | JSON CRUD, skip/limit/nextLink, автоматизована колекція запитів |
| C6, C7 | Окрема адаптивна сторінка події на Bootstrap, метадані та SEO-аудит |
| F2 | Пошук місця у формі події після трьох символів із затримкою та запитом до сервера |
| C8, F1 | Мапа всіх місць із фільтрами та діаграма подій |
| B2 | Корисні погодні дані зі стороннього API для місця і дати події |
| C10, C11 | Живе оновлення статусу події через SignalR та виміряне порівняння транспортів |
| B9 | Кешування безпечної відповіді API з коректним скиданням після змін |
| C4, QA2 | Docker Compose і наскрізні тести основних сценаріїв |
| C2, C3 | Публічне хмарне розгортання та автоматичне оновлення з main, якщо є доступ до хмарного облікового запису |

Інші завдання списку не заявляються виконаними. Окремий React-проєкт F5, OAuth C16, enterprise CRM B3, Web3 C20, агент C21 та MCP C22 потребують окремих, повноцінних реалізацій. Оцінка залежить від коду, захисту й довіри викладача; план не гарантує бали.

## Приймання

1. `dotnet build` завершується успішно з чистого клонування.
2. Локальна база створюється застосуванням migrations, тестові дані вводяться через UI або документованою командою.
3. Для кожної з трьох сутностей можна створити, переглянути, змінити та видалити запис; помилки форми зберігають введені дані.
4. Кожна наступна стадія додає перевірені сценарії та залишає рішення таким, що збирається.
5. Для заявленої зовнішньої інтеграції існує живий приклад або перевірюваний локальний тест, а обмеження явно записані.
